# メッセージとルームをつなぐ

メッセージの表に列を1つ足して、ルームの番号を持たせます。

## 表をあとから変える方法

ルームの表はできましたが、メッセージの側にはまだ手がかりがありません。`messages` の列は5つで、`room_id` が無いからです。

反映が済んだ設計図は、もう読まれません。あとから直しても表は変わらず、表ごとつくり直せば中の会話も消えます。

そこで、設計図をもう1本足します。「この表にこの列を足す」と書いて反映すると、いまの会話をそのままにして、列だけを増やせます。

列が増えると、いままでの会話にもその列の値が要ります。今回は 1 を入れる指定を書くので、これまでの会話はすべて1つ目のルームのものになります。

## 入れてよい列を増やす

もう1つ書き替えるのは `Message` です。送ったメッセージを残せるようにしたとき、「入れてよい列」を決めた1行を書きました。あの行に `room_id` を足します。

このあと送信をルームあてにすると、送られてくる中身にルームの番号が混ざります。許可しておかないと、その番号だけが表に入りません。

## 実践: メッセージにルーム番号を持たせる

前のセクションで `cd chat-app` を済ませたターミナルを、そのまま使います。作業部屋を開き直したときは、`cd chat-app` を打って1つ用意してください。この節ではブラウザを使わないので、`php artisan serve` は動いていなくてもかまいません。

やることは4つです。設計図のファイルを出し、そこに1行書き、データベースに反映して、`Message` を書き替えます。

1つめは、設計図のファイルです。ターミナルで出してもらいます。

```bash
php artisan make:migration add_room_id_to_messages_table
```

出力例です（ファイル名の数字は、打った時点をもとに決まります）。

```text
   INFO  Migration [database/migrations/2026_07_29_082530_add_room_id_to_messages_table.php] created successfully.
```

うしろの `add_room_id_to_messages_table` から、`messages` に列を足す形のファイルができます。

2つめは、その設計図に列を1行書くところです。左のファイル一覧で `migrations` を開き、いちばん下に増えたファイルを押してください。

以下は主要部分の抜粋で、いま読むのはここだけです。

```php
        Schema::table('messages', function (Blueprint $table) {
            //
        });
```

`Schema::table('messages', ...)` は、すでにある表を変えるという指示です。列を書く場所には、何も書かれていない印の `//` が入っています。

開いたファイルには、この同じ形がもう1つ下にもあります。`public function up` と書かれた行の下にあるほうが、いま書き替えるほうです。下の `public function down` のほうは、そのままにしておいてください。

その `//` の行をまるごと選んで、次の1行に置き換えてください。

```php
            $table->foreignId('room_id')->default(1)->constrained();
```

ルームの番号を入れる列を足す指示が、この1行に入っています。`->` でつないだ長い形は、そのまま写せば足ります。

置き換えたあとは、この形になります。

```php
        Schema::table('messages', function (Blueprint $table) {
            $table->foreignId('room_id')->default(1)->constrained();
        });
```

3つめは、データベースへの反映です。

```bash
php artisan migrate
```

出力例です。

```text
   INFO  Running migrations.

  2026_07_29_082530_add_room_id_to_messages_table ................ 10.73ms DONE
```

末尾に `DONE` と付いていれば、列が増えています。

!!! failure "よくあるエラー"

    `->default(1)` を書かずに反映すると、末尾が `DONE` ではなく `FAIL` になり、長い英語が続きます。その中に、次の文字ではじまる行があります。

    ```text
      SQLSTATE[HY000]: General error: 1 Cannot add a NOT NULL column with default value NULL
    ```

    **原因**: いままでの会話に入れる番号が決まらないので、列を足せません。

    **対処法**: 設計図の1行に `->default(1)` を入れて、`php artisan migrate` をもう一度打ってください。止まったときは列も増えていないので、打ち直すだけで通ります。

4つめは、`Message` の側です。`app` の中の `Models` にある `Message.php` を開き、ファイル全体を次の内容にまるごと置き換えてください。

```php title="app/Models/Message.php"
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class Message extends Model
{
    protected $fillable = ['name', 'body', 'room_id'];
}
```

変わるのは1行だけで、角かっこの中に `'room_id'` が増えます。

!!! warning "注意"

    `'room_id'` を足し忘れても、いまは何も起きません。画面いっぱいに英語のエラー画面が出たのは、この行そのものが無かったときです。中の1つが足りないだけでは止まりません。困るのはこのあと送信をルームあてにしたときで、どのルームで送っても全部が1つ目のルームに入ります。エラーの言葉はどこにも出ません。送ったメッセージがそのルームに増えないことが、気づくための手がかりです。そのときは、この行を確かめてください。

最後に、列が増えたか確かめます。

```bash
php artisan db:table messages
```

```text
  main.messages ..............................................................
  Columns .................................................................. 6

  Column ................................................................ Type
  id integer, autoincrement .......................................... integer
  name varchar ....................................................... varchar
  body text ............................................................. text
  created_at datetime, nullable ..................................... datetime
  updated_at datetime, nullable ..................................... datetime
  room_id integer ................................................ '1' integer

  Index ......................................................................
  primary id ......................................................... primary

  Foreign Key .......................................... On Update / On Delete
  room_id references id on rooms ....................... no action / no action
```

列の一覧のいちばん下に `room_id` が増えました。その右の `'1'` は、番号を指定しなかったときに入る値です。いままでの会話にも、この 1 が入っています。下の `Foreign Key` の2行は、読まなくてかまいません。

ここまでで、チャット画面の吹き出しの並びは何も変わりませんが、これで合っています。次のセクションでルームの一覧をつくると、目で見える変化が出ます。

**確認**: `php artisan db:table messages` と打つと、`Columns` の右が `6` になり、列の一覧に `room_id` が並びます。

## まとめ

- 列を足す設計図をもう1本足せば、中の会話をそのままにして表を変えられる
- 足した列には 1 が入るので、いままでの会話は1つ目のルームのものになった
- 画面から送られてきたものを保存するときに入れてよい列へ、`room_id` を足した

次のセクションでは、ルームの一覧を出す画面をつくります。一覧から選ぶとチャット画面のアドレスが変わり、そのルームのメッセージだけが並ぶところまで進みます。
