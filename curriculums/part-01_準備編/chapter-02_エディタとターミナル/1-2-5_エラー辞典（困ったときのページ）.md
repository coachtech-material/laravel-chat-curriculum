# エラー辞典（困ったときのページ）

困ったときに戻ってくるページなので、いま通して読む必要はありません。

## この辞典の使いかた

エラーの言葉で調べるときに開くのが、このページです。

探すときは、原因ではなく **画面に出ている言葉** で探します。原因は、たいてい探しあてたあとで分かります。自分の画面と見比べて、近い見出しを開いてください。見出しに並ぶ言葉は、どこかに打ち込むものではありません。

言葉が出る場所も、項目ごとに書いてあります。はじめのうちはターミナルに出るものがほとんどですが、自分のアプリをブラウザで動かすようになると、ブラウザの画面いっぱいに出るものが増えます。同じ言葉が、場所を変えて出てくることもあります。

まだ習っていない道具の名前が出てくる項目もあります。ここに載っている言葉を見かける場面は、先へ進むほど増えます。

## 画面に出る言葉から探す

### command not found と出る

```text
bash: sl: command not found
```

ターミナルに出ます。打った言葉が、コマンドとして見つからなかったという表示です。まん中に入るのは、自分が打った言葉です。多いのはつづりの打ち間違いなので、1文字ずつ見直して打ち直します。つづりが合っているのに直らないときは、全角の文字が混じっていないか見直し、入力を半角に切り替えます。

### No such file or directory と出る

```text
bash: cd: practise: No such file or directory
```

ターミナルに出ます。その名前のファイルやフォルダが見つからないという表示です。まん中に入るのは、探しにいった名前です。名前のつづりが違っているか、いる場所が思っているところと違っています。`ls` で名前を並べて見比べ、いまいる場所はコマンドを打つ行の表示で確かめてください。

### Could not open input file と出る

```text
Could not open input file: artisan
```

ターミナルに出ます。うしろに付くのは、動かそうとしたファイルの名前です。原因は2つで、名前のつづりが違っているか、いる場所が違っています。`ls` と打って、目当ての名前が見えるか確かめてください。目当ての名前が見えているのにこの表示が出たときは、`hello.php` を `helo.php` と打ったようなつづりの違いなので、打ち直します。`chat-app` の名前が見えたときは1つ外にいるので、`cd chat-app` を打ってからやり直します。

### ＜ や ＞ が画面にそのまま出る

日本語入力のまま打つと、`<` と `>` が全角の `＜` `＞` に変わります。見た目は似ていても別の文字なので、印としては働きません。入力を半角に切り替えて、その行を打ち直してください。

### 画面が変わらない・真っ白になる

ブラウザに、前のままの表示か、何もない白い画面が出ます。まず編集エリアのタブに出ている名前を見てください。別のファイルを開いたまま打っていることがあります。名前が合っているなら、その画面を開いているブラウザのタブを再読み込みします。Laravel でつくった画面は、ファイルを書き替えても自分では変わりません。開き直したときに、書き替えた内容になります。

### 作業部屋が見つからない・止まっている

しばらく触らずにいると、作業部屋は自動で止まります。止まっても中身は消えません。「Code」から「Codespaces」の一覧を開き、並んでいる名前を押せば続きから始められます。一覧に何も並んでいないときは、長く開かないままだったために作業部屋そのものが消えています。書いたものを消えない場所に残す手順は、次のセクションで扱います。

**ここから下**: この先の章で出会う言葉です。全部に出会うわけではないので、困ったときに見出しを見に戻れば十分です。

### Internal Server Error と出る

ブラウザの画面いっぱいに英語が出たときの、いちばん上の1行です。何かが失敗したという合図だけで、中身は書かれていません。読むのは、そのすぐ下に続く3行です。

```text
Internal Server Error
ParseError
routes/web.php:11
syntax error, unexpected token "}", expecting ";"
```

2行目がエラーの種類で、画面でいちばん大きな文字です。3行目が、どのファイルの何行目かを指す小さな灰色の1行です。4行目がエラーの中身です。まず3行目のファイルを開き、そのうえで4行目の言葉をこのページで探してください。

### Fatal error と出る

ターミナルに出ます。英語が何行も続き、その中に `vendor/autoload.php` というファイルの名前が入っています。チャットアプリの土台をつくるコマンドが、途中で止まっていたときの表示です。左のファイル一覧では見分けが付きません。`chat-app` を右クリックして「完全に削除」で消してから、同じコマンドを打ち直してください。

### is not empty. と出る

```text
Project directory "/workspaces/chat-lesson/chat-app" is not empty.
```

ターミナルに出ます。チャットアプリの土台をつくるコマンドを、中身の入っているフォルダに向けて打ち直したときの表示です。`chat-app` を右クリックして「完全に削除」で消してから、もう一度打ってください。

### Parse error / ParseError と出る

ターミナルでは `Parse error`、ブラウザの画面いっぱいに出るときは空白なしの `ParseError` になります。どちらも、書いたプログラムの形が崩れているという表示です。記号の閉じ忘れがほとんどで、そのあとに `syntax error`・`Unclosed`・`Unmatched` のいずれかが続き、行の番号も出ます。その行と1つ前の行の記号を見直します。番号が2つ並ぶときは、小さいほうから見ます。

`.blade.php` のファイルでは、出ている数字が当てにならないことがあります。そのときは数字を追うかわりに、`@foreach` と `@endforeach` の数が1対1でそろっているかを数えてください。`routes/web.php` が崩れているときは、直したいページだけでなく、ほかのページも出なくなります。直せば全部もどります。

### Unmatched '}' と出る

```text
Parse error: Unmatched '}' in /workspaces/chat-lesson/practice/talk.php on line 8
```

ターミナルにも、ブラウザの画面いっぱいにも出ます。`}` を1つ多く打ったという表示です。閉じ忘れとは逆で、閉じるほうが余っています。`{` を打つと `}` が自動で足されるので、そのあとに自分でも打つと2つ並びます。`on line` のうしろの数字が、その余った `}` の行をそのまま指すので、その行を消してください。ブラウザに出るときは、大きな文字の `ParseError` の下に続く `routes/web.php:11` のような1行が、同じ行の番号です。

### アプリの画面が開かない

ブラウザにページが出ません。自分のアプリを動かしておくコマンドが止まっています。ターミナルで `php artisan serve` を動かし直してください。

### Address already in use と出る

```text
  Failed to listen on 127.0.0.1:8000 (reason: Address already in use)

   INFO  Server running on [http://127.0.0.1:8001].
```

ターミナルに出ます。`php artisan serve` が動いたままのところに、もう一度同じコマンドを打った表示です。止まらずに別の番号で動き出すので、うまくいったように見えます。`Ctrl` キーと `C` キーを同時に押して、いま打ったほうを止めてください。もとの1つは動いたままです。

### 404 と Not Found が出る

ブラウザに、白い画面と小さな2つの言葉だけが出ます。開いた URL に対して、出す画面が決まっていないという表示です。URL のつづりが、自分で決めた住所と同じかどうかを見比べます。アドレスの途中で `/` が2つ続いていないかも見てください。末尾に付いた `/` は、そのままでかまいません。自分で URL を打っていないのにこの画面になったときは、消したメッセージが残っている古い画面で「削除」をもう一度押しています。先に戻るボタンを押してチャット画面にもどり、その画面を再読み込みしてください。

白い画面ではなく、破れた紙のような絵と「このページが見つかりません」が出たときは、別の原因です。アドレスをよく見ると、途中に `:8000` が挟まっています。作業部屋の中だけで通じる住所が、そのまま送り返されています。`bootstrap/app.php` に `$middleware->trustProxies(at: '*');` の1行があるか確かめてください。

### Undefined variable と出る

ブラウザの画面いっぱいに出ます。画面側で使っている名前と、渡した側の名前が食い違っています。両方を見比べて、同じつづりにそろえます。ターミナルで PHP を動かしたときは、その場所だけ空のまま表示が続きました。Laravel ではそこで止まり、前に書いた見出しや文章も出なくなります。空欄を探しても見つかりません。

### View [chat] not found. と出る

ブラウザの画面いっぱいに出ます。角かっこの中に入るのは、ルートで呼び出した画面ファイルの名前です。その名前のファイルが `resources/views` に見つかりません。名前のつづりと、置いてある場所を見比べてください。この表示のときだけは、下の小さな1行に出るファイルが `vendor` で始まっていて、自分の書いたファイルではありません。

### {{ }} が文字のまま画面に出る

```text
{{ $name }}さん、こんにちは
```

ブラウザに出ます。エラーは出ず、画面はふつうに表示されたまま、`{{ }}` で囲んだところが波かっこごと文字になります。画面のファイルの名前が `.blade.php` で終わっていません。`chat.php` のように `.blade` が抜けていると、`{{ }}` は印として働きません。ファイルを右クリックして「名前の変更...」を選び、`.blade.php` の形に直してください。

### Nothing to migrate. と出る

```text
   INFO  Nothing to migrate.
```

ターミナルに出ます。これはエラーではありません。設計図はすべて反映済みだという知らせです。列を書き足す前に反映してしまったあとで設計図を直しても、この表示が出るだけで表は直りません。`php artisan migrate:fresh` と打つと、表をつくり直せます。

### no such table と出る

ターミナルとブラウザのどちらにも出ます。データを入れる相手の表が、まだできていません。表をつくる `php artisan migrate` を先に済ませてから、データを入れ直します。

### MethodNotAllowedHttpException と出る

ブラウザの画面いっぱいに出ます。その下に、次の1行が続きます。

```text
The POST method is not supported for route chat. Supported methods: GET, HEAD.
```

フォームの送り先にした住所では、届けるための行き方を受け付けていません。先に戻るボタンを押して、もとの画面にもどってください。`routes/web.php` に `Route::post` で始まる行があるか、フォームの `action` に書いた住所とそろっているかを見比べてから、送り直します。

はじめの `The POST` のところが `The PATCH` や `The DELETE` になっていることもあります。フォームに `@method('PATCH')` や `@method('DELETE')` を書いて送ったときの行き方です。その場合は `routes/web.php` に `Route::patch` や `Route::delete` で始まる行があるか、`@method` に書いた言葉とそろっているかを見比べます。行の末尾の `Supported methods:` のうしろに、その住所がいま受け付けている行き方が並んでいます。

### 419 と Page Expired が出る

ブラウザに、数字とひとことだけが出ます。送信フォームに付ける合言葉の1行が抜けているか、ページを長く開いたままにしてから送ったときに出ます。先に戻るボタンを押して、チャット画面にもどってください。`<form>` の中に `@csrf` の1行があるか確かめ、あればそのまま送り直します。

### Add [name] to fillable property と出る

```text
Add [name] to fillable property to allow mass assignment on [App\Models\Message].
```

ブラウザの画面いっぱいに出ます。表のどの列に入れてよいかを、モデルに教えていません。角かっこの中に出るのが、その列の名前です。モデルのファイルに `protected $fillable = ['name', 'body'];` の1行があるか確かめてください。直したら、先に戻るボタンを押してチャット画面にもどり、もう一度送ります。

### NOT NULL constraint failed と出る

ブラウザの画面いっぱいに出ます。その中に、次の文字ではじまる行があります。

```text
SQLSTATE[23000]: Integrity constraint violation: 19 NOT NULL constraint failed: messages.body
```

欄を空のまま送ったときの表示です。データベースは、空のままの列を受け付けません。末尾に出ているのが、空だった列の名前です。先に戻るボタンを押して、チャット画面にもどってください。文字を入れてから送り直します。

### 「メッセージを入力してください」と出る

チャット画面の入力欄の下に、赤い文字で出ます。これはエラーではありません。メッセージを空のまま送ったことを知らせる表示です。文字を入れてから、もう一度送ってください。

### Target class does not exist と出る

ブラウザの画面いっぱいに出ます。送られてきた内容を受け取る係の名前が見つからないという表示です。大文字と小文字の違いも含めて、名前のつづりを見直します。

## まとめ

- 困ったときは、原因ではなく画面に出ている言葉からこのページを探す
- 見出しの言葉は自分の画面と見比べるための目印で、打ち込むものではない
- ブラウザの画面いっぱいに英語が出たときは、2行目から4行目までを読む
- いま意味が分からない項目は飛ばしてよく、詰まるたびにここへ戻ってくればよい

次のセクションでは、今日さわった分を記録して、自分の GitHub に上がったことを確かめます。あわせて作業部屋を止めて、もう一度ひらくところまでやっておきます。
